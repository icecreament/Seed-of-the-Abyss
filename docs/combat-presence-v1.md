# 四职业战斗出手姿态 · presence v1

## 目标与判断依据

继续向「帅 + 爽」推进，把已完成肖像的气场带进战斗小人，不加新职业/数值/粒子系统。修改前先核对上一轮 115 份冻结文件，零漂移；然后捕获实际生成的 8 套战斗图集、8 套肖像及每个 32×32 单元的 RGBA 哈希。

实际图集显示，旧攻击主要在转动武器，身体与双脚变化很小。原 Player 与 RunScene 在第 8 单元就结算近战/生成弹丸，而第 8 单元画的还是预备动作。因此本轮不是加攻速或延迟伤害，而是让第一张画面已经表现「出手」，后续依次承势、收招、归位。

## 生产改动

- `src/assets/CombatStance.ts`：仅绘制使用的职业姿态表。四个既有攻击单元保留原生时间；按职业提供躯干前倾、重心、步幅。
- `src/assets/ParasiticWarden.ts`：守望者撑开站姿、肩臂连到前方剑柄，剑刃具有实体切面；压剑后收回镇守，不只是原地转一条线。
- `src/assets/AbyssHeroes.ts`：掠夺者用双臂/前倾重心带动宽刃，影行者低伏交替出匕、围巾随扑刺后扬，棘语者抬掌并将种核法杖向前倾压后收回直立，仍不是弓手。
- `src/assets/HeroAwakening.ts`：仅同步战斗攻击叠层的位置。感染肩翼约束在单元内部，移除攻击中留在旧手腕位置的装饰，避免第三把浮空匕首等错位。所有肖像绘制不变。

没有改 Player、RunScene、职业数据、碰撞、伤害、命中范围、攻速、冷却、缓冲、音频、战斗特效或输入代码。上一轮鼠标归属修复保留。

## 像素与时机证据

- 八套图集均仍为 448×32，14 个 32×32 单元，最近邻过滤；32 个攻击单元改变，其他 **80 个单元**逐像素不变。
- **八套肖像 RGBA 全部不变**。不把 PNG 编码字节当成像素判据。
- 32 个攻击单元都保留左右靴底 y28 锚点；用加宽绘制域排查向前/向下超出单元的绘制，避免正常画布把超出的刀尖裁掉还看不出来。
- 真实鼠标点击的八个基础/觉醒外观夹具中，全部在 POST_RENDER 实际看到 8→9→10→11，而不是只检查动画配置。
- 三个近战职业都在接触单元 8 实际扣血；棘语者在单元 8 生成一发原弹丸，随后按实际飞行命中。伤害仍为该隔离夹具中的 16/19/15/10。
- 此处觉醒是明确的仅外观夹具，未注入觉醒突变伤害；不能拿它冒充职业觉醒机制验证。原觉醒浏览器与正常整章样本另行验证真实突变流程。

## 基线更新不等于放宽断言

旧 `scripts/fixtures/portrait-presence-combat-rgba.json` 保留原样，继续记录历史「仅改肖像」快照。本轮有意修改战斗攻击美术，因此肖像检查改为匹配新登记的 `combat-presence-rgba.json`，仍逐一精确比较八套图集的 RGBA。新 `combat-presence-before.json` 独立保留旧实际 PNG/逐单元哈希，新增检查严格禁止修改任何其他单元和肖像，且检查躯干部位确实改变，不仅是换一个哈希或动一像素。

## 保留的失败与修正

- `typecheck-01.txt`：动态数组强转 Point 被 TypeScript 拒绝。改为显式 readonly Point[] 元组集合，没有通过 unknown 绕过检查。
- `checks-01`：跨 Run 重开时，测试观察器未恢复原方法，包装引用了已销毁玩家并引发异常。观察后恢复原方法，再开始新场景；没有改变生产代码或减少原方法调用次数。
- `checks-02`：敌人 speed=0 不代表不会近身出招，原 AI 蓄力仍能推进并造成接触伤害，破坏纯美术夹具的稳定性。明确将此专项目标的 AI 关闭，保留真实受伤/弹丸/普攻路径和 HP/属性不变断言；不把这个夹具声称为自然对战。
- `checks-03`：靠近地图下缘时相机受边界约束，角色并不在画布正中心。固定屏幕瞄准点导致棘语者弹丸偏离，固定截图区域还会切到靴底。改为使用相机实际 worldView 换算目标位置与裁切位置，没有改命中条件或弹丸数值。
- `checks-04`：修正夹具后 13/13 新专项通过，浏览器无异常；原失败均保留。
