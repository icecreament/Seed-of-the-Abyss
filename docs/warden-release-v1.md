# 守望者：付过格挡代价的重斩 · release v1

日期：2026-10-24。继续「要玩起来很爽」，把已有职业招牌从外圈特效带回角色身体。本轮同时保留并修正一个独立复现的新按下缓冲时钟问题，不把它冒称纯美术改动。

## 实际断层与改前证据

开始前核对上轮 `thorn-cue-v1/verified` 的 155 份冻结文件，零漂移。改前真实引擎受控录帧：真实 Q 后经过原无敌窗口，再明确调用一次实际 `applyDamage(20)` 形成格挡付款（5 点实际受伤、15 点反击压力）；随后真实鼠标新按下，普通原重怪即时损失 31 HP。角色仍使用 `hero_warden` 原 8→9→10→11 普通挥击，主要靠外圈壁垒特效说明反击。

`before/` 是该受控遭遇的原始 POST_RENDER PNG、状态与当时 23 套图集像素哈希，不是自然挨打或整章录像。最早捕获器在 Run 活跃时读回纹理，原角色在配置夹具前已经损失了一些 HP；不能把前后完整遭遇当成同一初始状态或自然表现对照。实际付款、目标原始 HP、攻击损失均单独记录。最终捕获器移除了这段活跃局内纹理序列化，独立证据不覆盖原记录。

## 让身体兑现，而非叠更多光效

- 基础/觉醒各增加一张独立 128×32、四格、最近邻图集：`strike_warden_reprisal` 与 `_awakened`。旧英雄、肖像、敌人以及棘语者收掌共 **23 张既有图集**全 RGBA 不变。
- 动作是**撑开承重脚 → 双臂压过剑势 → 收回重心 → 归守**。首格已在接触/切入，不画与即时伤害相矛盾的前摇。
- 角色躯干、木质臂与站姿确实变化，不只是旋转武器。每格两只靴底保留 y28，扩大绘域检查没有单元外落笔。新图集不改变尺寸、碰撞体、原点、移动速度或命中范围。
- 觉醒层使用同一承重姿态，途中变身保留实际同格/剩余时间；向左释放继续使用原镜像规则。
- 不添加新的泛光、闪屏或粒子；原近战命中、原壁垒反击特效保留。

## 由已提交攻击拥有时间

`WardenRelease.ts` 只把已有普通攻击 `attackPoseTimer` 映射为四格。只有原规则实际消费了反击压力的已接受新攻击才开始该姿态。基础攻速下原时间仍为 250ms，快攻速夹具为原 100ms；没有新固定时长、第二个推进时钟或额外停手。

这与棘语者的“实际种子 HP 损失确认”不同：守望者原规则在付费挥击提交时消费压力，即使落空也会消费。因此本姿态表示**付费重斩已出手**，不是虚构命中确认；落空不追加伤害或返还压力。

- 新冲刺、实际新受伤、死亡、战斗停止、换层和选择面板都会取消。
- 原无敌拒绝的伤害不打断；冷却拒绝的点击不续时/重播。
- 如果反击提交时原受伤帧仍在播放，受伤保持优先，但攻击照常即时结算、时钟照常走；伤闪结束后只显示当时应有的格，绝不等受伤结束再偷偷重开 250ms。
- 舒适/减少动态不新增重斩动作；途中关闭时恢复同相普通挥击，不修改原伤害、冷却与碰撞。
- 暂停/命中停顿冻结原攻击时钟；无全局定时器、隐藏续时或监听对象增长。

## 分清两件独立故障

### 测试夹具返回整只 Enemy，跨端序列化耗过了反击窗口

最初触屏检查得到普通 16 点，而不是 31 点。随后独立诊断发现，`page.evaluate(() => window.releaseEnemy())` 会把整个 Phaser Enemy 连同大量引擎引用返回测试端。独立样本实际耗时约 **4719ms**；轨迹中生成目标时有 15 压力，再次触摸时压力已按原规则过期。即使生产缓冲修复已存在，重现该错误夹具仍然得到普通 16 点。这不是新的姿态吞伤害，也不能用延长原 1200ms 反击有效期来“修”。

正确夹具只创建目标并读取必要数值，实际新点击仍要求真实付费、原 31 点伤害与原监听数量，未降低断言。只读包装逐一转发原方法一次，诊断轨迹保存。原失败保留在 `checks-02/03`，不累计为最终通过数。

### 独立确认：长帧会把新按下先扣成旧输入

另开的真实 `touchStart` 受控 **200ms 帧间隔**复现了生产代码中的另一件问题：`readInput` 先设新攻击缓冲为 140，然后本帧 `updateEntity(200)` 又扣掉整个先前帧间隔；新按下被当成按住连发，只打普通 16 点、压力仍保留。

修复只让当前采样的新边沿补偿这一次已经过去的帧间隔：`queueAttack(elapsedFrameMs)`，再由同帧正常扣回。采样后仍是原 **140ms 战斗时间窗口**，以后照常过期，无新边沿不续时。`queueAttack()` 默认调用保持原夹具/直接调用语义，原攻击冷却和反击压力时钟没有补偿或延长。

同样真实触摸、同样 200ms 控制步骤，修前目标 86→70（16）、压力还在；修后 86→55（31）、压力按原规则消费、重斩进入首格。`touch-hitch-before.json`、`touch-hitch-after.json` 保存完整转发轨迹。0/16/139/140/200/500ms 的新边沿预算、随后 139+1ms 过期、非法偏移以及已过期压力不能再兑现均单独检查。不能将原触屏夹具故障和这个生产输入故障混为同一因果链。

本轮因此包含真实输入正确性修复；后续自然样本的变化不归因于“仅仅换了动作”。

## 旧测试与自然策略没有被放宽

四份旧自然脚本只增加实际视觉状态读取、严格图集/时钟/受伤优先的契约；守望者反击路线另增加只读 POST_RENDER 状态观察和至少一次真实姿态可见的更强覆盖断言。无动作时仍要求原英雄图集，不能只凭 key 前缀或“是新增图集”就放行。

`natural-policy-provenance.json` 保存精确登记替换。逆向剥离这些视觉观察、契约和新增覆盖断言后，完整旧脚本与改前文本一致，连选择优先级、输入时机、移动、Q/冲刺策略和原结果/真实命中断言一起守护。没有为展示新动作改控制器，也没有额外指定掉落、强迫停手或改伤害。

所有原始字节在 `baseline/`，增量在 `incremental.patch`。新增入口：`test:warden-release` 与 `test:warden-release:browser`。正式冻结运行及结果将在下节记录，不能借旧全绿冒充当前版本。
