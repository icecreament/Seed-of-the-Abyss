## 本轮目标

只验证两张图：一张主角设定图、一张 PC 战斗界面效果稿。确认风格后，才进入待机／攻击动画制作与游戏接入。本目录里的提示词不是图片交付物。

## 与现有项目的对齐

- 项目为 Phaser 俯视角 2D 动作游戏，当前角色与场景采用程序生成的像素素材。
- 当前实际职业为 warden、reaver、shade、thorn 四种，而非早期 README 中的三种。
- 本轮选 warden 作为主角样板，不新增职业或技能机制。
- 保留现有深紫背景、青绿生命／守卫配色、紫色技能、红色危险的基础视觉关系。
- 战斗 HUD 只展示现有的生命、攻击／冲刺／技能就绪状态、击杀数、楼层与楼层进度、种子阶段、暂停。不额外设计魔力、经验、背包、任务或小地图。
- 深渊精华在死亡后结算；不把它画成战斗中可拾取的货币资源。

## 视觉方向：被深渊植物寄生的守卫

关键词：人类尚存、甲胄破损、根系缝合、胸核呼吸、克制荧光、遗迹中的求生者。

主角是仍在抵抗寄生的守卫，不是枝叶茂盛的森林德鲁伊，也不是已经完全怪物化的树人。

### 固定身份锚点

1. 破损的灰白面甲，眼部是狭窄暗缝，不做两颗高亮激光眼。
2. 胸骨中央一枚种子核心：苍白青绿光，根系像缝线一样穿过胸甲。
3. 角色自身左肩为不对称木质寄生护肩，块面简洁，不长巨大树冠。
4. 角色自身右手持短阔的缺口铁剑，便于后续近战动作；不添加盾牌等新玩法暗示。
5. 暗紫短披布、磨损铁甲、人类双腿和靴子；轮廓重心低而稳。
6. 高亮只集中于胸核与少量根脉。武器、全身轮廓不全部发光。

## 图一：主角设定图

建议输出：1536×1024 横版 PNG；角色设定用途，不能直接作为游戏精灵图集使用。

- 左侧约 55%：全身三分之四正面主视图，双脚完整落在画内，待机持剑姿势。
- 中间约 25%：同一角色的侧面与背面小视图，保持甲片、武器、肩部与寄生位置一致。
- 右侧约 20%：胸核、寄生肩甲、剑柄的细节研究和少量色块。
- 主视图可用手绘概念稿表现材质，小视图必须保持清楚块面，便于后续像素化。
- 俯视角适配重点：顶面面甲、肩部不对称、胸核与剑的方向；不能仅依靠细小花纹辨识身份。
- 第一张图不混入战斗 HUD，也不混入动画帧或多种职业。

## 图二：战斗界面效果稿

建议输出：1536×864 横版 PNG；PC 布局风格验证，不是已实现游戏截图。

- 真正的俯视角 2D 战场，不做电影镜头或强等距视角。
- 沿用当前像素美术方向：像素边缘清楚、块面稳定、少量局部光晕；不做写实 3D。
- 环境：开阔的地下遗迹，碎石地砖、低矮残墙、少量根系和远离战斗中心的枯败植物。
- 主角在中心附近，角色总高度约占画面高度 6%–8%，能看见面甲顶面、左肩寄生块、右手剑及胸核。
- 4–6 个可区分轮廓的敌人从外围接近，保留脱身路径；敌人攻击提示以短红弧／红边界表达，不依赖红绿颜色差异。
- 地面暗、角色轮廓清楚、敌方危险信号优先，不用雾气和装饰遮住碰撞范围。

### HUD 构图

- 左上：紧凑的半透明暗石板，守卫头像／胸核标识、生命条、生命数值、击杀数。
- 右上：楼层与细进度条，旁边提供暂停入口。进度标注楼层进度，不伪装成经验条。
- 下方中央：攻击、冲刺、技能三个紧凑槽，分别使用剑、冲刺轨迹、根系护环图标；提示 LMB / SHIFT / Q。
- 左下：职业与种子阶段的轻量标记。
- 装饰根须只在面板角落，绝不穿过数字、冷却遮罩或条形区域。
- 至少约 70% 画面保持为清晰战斗区域。
- 不画手机虚拟摇杆。本轮先锁定 PC 风格；手机横屏布局之后单独适配，不能直接缩小 PC HUD。

图片内文字的拟定内容：生命 112/140、击杀 23、第 03 层、守卫、种子阶段 I，以及 LMB / SHIFT / Q。若生成文字不准确，后续用代码排版，不能将错误文字当作最终 UI。

## 之后的动画制作约束（本轮不执行）

- 待机：呼吸、胸核明暗、少量根须收缩；脚底锚点不漂移。
- 攻击：保持右手持剑，必须有预备、挥击、回收；剑光与命中提示分开处理。
- 以现有 Player 的脚底原点、碰撞与 300ms 守卫攻击冷却为接入约束；不能把概念图直接裁切冒充生产动画。
- 先确认最终精灵尺寸、方向数及图集布局，再制作逐帧资产。四方向仅作为待评估起点。
- 颜色／装备／武器长度／发光部位在所有视图与帧中固定。

## 评审问题

1. 主角是否仍有“挣扎中的人类守卫”感觉，而不是树人或通体发光的怪物？
2. 是否接受“骨白面甲＋青绿胸核＋不对称木质左肩”的固定辨识？
3. 小尺寸下角色与敌人的攻击方向是否容易分辨？
4. UI 是否看起来属于同一世界，同时不抢战斗注意力？
