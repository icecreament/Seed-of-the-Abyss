# 影行者：尊重同帧的「攻击→冲刺」输入次序

日期：2026-10-26。整体目标仍为“要玩起来很爽”。这是一次真实操作衔接修正，不是增加技能、自动回避或宣称整体爽感已验收。

## 实际断点

已有影行者机制完整包含 Q 隐匿切入、220% 破隐、真实命中后 650ms 回身方向、600ms 普通冲刺冷却、方向输入覆盖及独立身体动作。问题不是缺少另一套提示或技能，而是 Run 每帧先执行 Player 的冲刺，再解析攻击。

修改前用真实 Q 和原生键盘复现：固定 500HP 静止 brute、编辑位置与零暴击、禁止刷新，仅用于行为诊断。为稳定覆盖同一帧，临时让引擎 loop sleep，按下原生 Space/Shift，再 wake 同时采样；这不是自然帧率分布或人类按键间隔证明。

| 输入先后 | 原结果 |
|---|---|
| 同帧 Space → Shift | 先向前冲，第一冲刺时目标仍为 500HP；稍后才造成 33 破隐伤害 |
| 同帧 Shift → Space | 同样先向前冲，符合优先脱险的意图 |
| 分帧 Space 命中 → Shift | 先造成 33，再使用原有反向冲刺 |

同帧前两种情况原代码都丢掉了用户的输入先后。修改前证据保留于 `output/shade-link-v1/before/`；不是从某次自然死亡反推因果。

## 现在的规则

只有以下条件同时成立，才在本帧把攻击结算放在原冲刺前：

1. 确实是**新的攻击按下**，其原生 DOM 时间戳严格早于本帧的冲刺按下。
2. 当前为影行者，仍在隐匿中、没有正在冲刺，攻击与普通冲刺均已就绪。
3. 原攻击缓冲和原冲刺缓冲仍有效；本帧没有 Q/技能输入，也没有未消费的技能缓冲。

随后先按原规则解析破隐攻击，再消费那一次已就绪的原普通冲刺。只有原实际 HP 下降确认的回身方向可以被消费。**不为了等动作动画而延迟冲刺**；快速回身可以截断破隐身体姿势，但已有实际刀口/伤害/交叉刃反馈保留。

- Shift 先按或时间戳相同：仍先闪避。
- WASD/摇杆方向仍优先，反向回身不是强制行为。
- 长按攻击/OS 键盘 repeat 没有新的攻击边沿，不获得这套优先级。
- Q 尚在切入、攻击冷却未好、冲刺冷却未好：仍走原顺序，不新增提前执行。
- 新按攻击故意空挥仍可破隐；只碎弹/未造成实际 HP 损失不能制造回身方向，随后冲刺仍沿原朝向/玩家方向。
- 不加冲刺次数，不返还冷却，不改伤害倍率、范围、位移参数或无敌预算。
- 这**有意改变了对应输入的结算先后与实际连招行为**，不是“纯展示改动”，也不能声称其所有战斗时序都没变。

## 实现范围

- 新增 `src/input/AmbushInputOrder.ts`：仅保存当前输入采样内第一攻击/冲刺的原生时间戳及技能否决位。键盘和鼠标/触屏的 Phaser 回调可能不按物理发生次序交付，所以比较同一 DOM 时钟的时间戳，而不是回调调用次序。每次读取后清空，无跨帧新队列/新时间窗口，存储固定三项；平局保留防御冲刺优先。
- `src/input/VirtualControls.ts`：新按攻击/冲刺/技能时可回报原生时间戳。几何、手指所有者、摇杆、拖拽瞄准、冷却绘制和消费方式不改；两指同一个原生事件的相同时间戳仍优先冲刺。
- `src/entities/Player.ts`：`updateEntity` 默认行为不变，仅对合格的新影行者组合返回“需要在攻击后完成冲刺”的布尔值。`resolveBufferedDash` 只消费原已有效的冲刺缓冲，不能授予次数、跳冷却或延长缓冲。其他职业及不合格组合不会执行第二次机会性冲刺检查。
- `src/scenes/RunScene.ts`：记录有效边沿，采样后清空；只有 Player 明确返回已暂缓的合格组合才在真实攻击后消费冲刺并提交原战斗事件。命中停顿后重新冻结刚切换的冲刺动画，避免动画偷偷走、逻辑却冻结。原有焦点丢失/暂停/选择/换层/结算/退出边界同时清空新排序信息。

Player 的构造数值、`tryAttack`、`performDash`、`performSkill`、`applyDamage`、冷却查询与原缓冲方法完整文本保持相同；旧物理/碰撞/伤害/觉醒/图像/音频文件不变。上一轮 323 份冻结输入中只有上述三个既有文件变化，唯一新增生产文件是 AmbushInputOrder。

`output/shade-link-v1/input-order.diff` 为相对本轮已保存基线的审阅差异，不把整个脏工作区当作本轮改动。范围审计逆向移除声明的 19 个带上下文差异组后，逐字节重建三个原文件，包含原 CRLF。

## 新验证及保留的失败

- 输入模型 **7/7**，其中一项含 50000 次确定性混合操作，不称作五万项检查。覆盖真实先后与回调先后分离、平局、防御优先、技能否决、跨帧清空、非法时间与固定存储。
- 浏览器目前专项 **17/17**。有显式同帧夹具，也有六次不暂停引擎、不改时钟的正常实时原生连续输入；另覆盖键盘、鼠标、双指触屏、方向覆盖、冷却/缓冲、Q 切入/攻击恢复、空挥/只碎弹、长按隔离、命中停顿和生命周期。触屏为模拟设备，不是实体手机。
- `exploratory-browser-1`：桌面用例通过，移动端用例失败。夹具用设计像素直接移动桌面鼠标，而移动端画布 CSS 尺寸较小，导致 Q 瞄准变成斜向；实际反向冲刺正确，夹具错误要求水平 -520。修正瞄准到 canvas 的 CSS 坐标，不改反向/伤害/冷却断言。`exploratory-browser-2` 15/15；补充实时输入与恢复边界后 `exploratory-browser-3` 17/17。旧失败报告保留。
- 首次范围审计的前三项通过，第四项因旧脚本 CRLF 与新脚本 LF 的查找分隔符不匹配而失败，记录保留在 `exploratory-scope-1.txt`。只对比较双方统一换行后检查同一完整只读规划函数；不是修改旧脚本或忽略规划逻辑差异。

## 正常速度实战与策略边界

新增 `scripts/check-shade-link-natural.cjs` 是**新的首层输入策略**：Q 前抬起长按攻击，隐匿时继续按原路线/危险评分接近，有实际刀距机会后松方向，再连续按攻击/Shift。读取原战斗状态，动作只用真实鼠标/键盘。不改刷新、属性、敌人位置、伤害或时钟，不调用 loop sleep/wake。

其只读路线/危险评分规划函数来自原 `check-shade-return-natural.cjs`，除 CRLF→LF 外完整逐字符相同；新输入策略不能冒充原控制器。另独立运行原脚本、原“先看见回身提示再按 Shift”的整章策略，用于兼容证明。

探索样本 `exploratory-natural-1`：首层 10.125 游戏秒、12 杀，95/95HP，2 次正常帧中真实合并的先刀后冲、2 次实际命中授权、2 次无方向反向冲刺。仅一次随机可行性样本，不能归因为本轮提高了生存率或证明无伤通关/职业平衡。

### 原生同帧与位移交叉核对

六次**正常实时循环、不 sleep、不改时钟**的原生连续输入夹具本次均实际落到同一输入采样；六次都先命中后反向冲刺。模型/受控样本还分别覆盖“反向回调交付”和“物理 Shift 先按”。不能把这六个固定目标样本当成所有玩家的帧率分布。

另外独立比对修改前/正式当前的三组原生捕获：同帧先攻击再冲刺的第一冲刺事件由“目标 500HP、vx=+520”变成“目标 467HP、vx=-520”；先冲刺仍为“500HP、+520”，分帧正常回身仍为“467HP、-520”。三组各自的最终原生固定步长实际位移均与旧捕获相同为 78 世界像素。这里报告的是夹具内固定步进观测值，不以 `140ms×520` 的理论乘积代替真实位置，也不宣称所有设备都精确 78。详见 `input-capture-crosscheck.json`。
