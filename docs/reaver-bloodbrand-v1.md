# 血棘追猎与三刀节拍（2026-10-22）

## 目标与范围

上一轮完成基础击杀追斩，但两种掠夺者专属突变还主要是「挂DOT」与「每三刀多伤害」。这轮把它们往不同的操作回报推进：

- **血棘刻印**：先刻伤、再选择消耗伤口追猎同一目标；适合盯住较硬目标。不是棘语者那种远程铺种／群体引爆。
- **第三次葬礼**：维持原有每三次实际普攻的群斩，新增三刀进度提示，让下一次环斩可预判。

它们仍是原突变池里的两个可同时持有的突变，不是新加的互斥天赋树、第二套觉醒美术或已经平衡完成的两个终局流派。目标「要玩起来很爽」仍需人工判断，不以自动胜利代替。

## 已实现规则

### 血棘的付费追斩

1. 只有持有`reaver_bleed`的掠夺者，才能用仍有未来伤害脉冲的流血伤口支付一次追斩；**不需要先杀一只怪**。没有突变、没有伤口或伤口已耗尽，就只能用原来的击杀票或普通攻击。
2. 保留原140ms新按键缓冲、原攻击冷却、方向与目标资格：正在朝刀外近敌移动，重新按下普攻；目标必须已实体化、有视线，处于原刀距之外至额外54px内。已有刀内目标时优先砍近敌。长按、后退、横移、墙后目标不自动花掉伤口。
3. **在踏进承诺时立即移除这名目标的剩余流血**，保存目标身份与尚未支付的脉冲数。踏进没有伤害，仍是480px/s、最多64px、原生墙碰撞、不带无敌、不追踪转弯。
4. 踏进结束后完成原普通攻击。只有这刀真正命中原目标，才把已支付的脉冲一次结清；其他被这一刀打到的敌人只承受正常攻击，不继承原目标的流血预算。到位失去视线时也不隔墙补刀。
5. 扑空、受击、普通冲刺、血涌取消、三选一／换层、死亡或结算均不退还已支付的流血，也不在下一次攻击／新房间补结算。原目标先死也不能重复结算死亡。
6. 结清这一刀不再给原目标重种流血；下一次正常普攻才能再次刻伤。不制造「一刀花掉旧伤口，又白送全新伤口」的无限循环。
7. 若同时有原击杀追斩票，优先以伤口支付时不额外吞票；票仍按原战斗时间到期，真实击杀仍正常刷新。无伤口的基础追斩规则保留。

### 伤害与回血账目

- 原流血3100ms存活窗口、1000ms脉冲、30%基础伤害与刷新时保留脉冲相位不改。卡片沿用「3秒」的原说明。
- 不写死「剩三跳」：普通新伤口通常剩3次；在下一跳仅余100ms时刷新3100ms，原时钟允许4次，标记会如实显示最多四道刻痕。
- 流血部分不吃普攻暴击倍率。每一跳先按目标当前受伤倍率独立取整，再求和，避免批量结算时悄悄改变总伤害。
- 白板19攻击、3次余跳：普通斩19 + 3×5 = **34**；普攻暴击时33 + 15 = **48**。露核1.25倍时23 + 3×7 = **44**，不是先把15随便乘一次再取整。
- 这是一记实际命中，使用原有一次命中回血／吸血结算，不虚构多次命中来额外回血。选择提前收割也意味着放弃原来等待多次流血命中的回血节奏。
- 顺带修正原DOT在单帧长卡顿时仅支付一次脉冲的问题：只在真实存活时间内补齐到期脉冲，不在3100ms后继续伤害，不对已经死亡的目标多打／多次结算。正常帧时的脉冲时点不变。

### 三刀提示与表现

- 环斩仍只在实际第三次普攻触发；踏步开始不算出刀，原110范围、90%基础伤害不改。
- 头顶三道短刃显示进度，前两刀逐步点亮，第三刀触发时短促点亮后复位。没有新增蓄力等待、强制停顿或屏幕闪白。
- 撕裂用目标局部双钩裂线与一次命中音，不冒充环斩觉醒演出；复用既有80个短效上限。地面追斩提示、血棘操作提示与伤口刻痕保持轻量，暂停只冻结战斗时间。
- 长说明改用能拆分连续中文的高级换行。触屏长文最多在18px至14px之间收敛，保持在原卡片正文区域内，不压标题或确认按钮。

## 迭代中发现的缺口

- 第一轮取消夹具先写`player.wantDash/wantSkill`再调用Scene.update，但真实readInput会覆盖这两个值，因此并未真的发送取消指令。改用真实场景的pending输入缓冲，三个取消分支均实际执行；原失败保留在`checks/`。
- 500次演出更新的对象上限测试最初把之后真正出刀新增的刀光／浮字也算进增长。改为在更新循环结束当场记录增长，不把正常攻击产物混入长时间对象泄漏断言。
- 桌面突变卡最初只验证上下边界，中文长段没有按字断行，截图中横穿相邻卡片，虽「21项通过」却不能证明布局合格。检查实际截图后修复生产换行，并把左右边界、标题间隔、确认按钮、触屏中英文全加进新检查。`checks-02/choice-zh.png`保留这个问题，不能拿旧绿勾当当前验收。

### 独立输入策略自然局：保留覆盖失败

|真实可选突变的优先级|整章结果|战斗秒|追斩开始／结束出刀|伤口付费开始／结算命中|环斩次数／命中记录|验收|
|---|---|---:|---:|---:|---:|---|
|血棘优先|胜利|73.26|10 / 10|0 / 0|37 / 58|**失败：未覆盖伤口付费追斩**|
|环斩优先|胜利|68.96|11 / 11|1 / 1|36 / 60|通过|

- 血棘优先并不强制给血棘。该局真实选择顺序是`shared_feast → reaver_cleave → reaver_bleed`，约57.91秒才取得血棘。最终虽胜利且有普通击杀追斩，仍触发`No wound-paid pursuit`原断言。没有删除断言、强塞掉落或重抽一局替换失败。
- 环斩优先局真实顺序是`reaver_bleed → reaver_cleave → shared_haste`，实际发生1次伤口付费开始及1次撕裂结算。这证明该独立策略的一次自然运行里确实使用了机制，不证明高覆盖率或两种构筑平衡。
- 追斩命中与环斩命中记录可能重叠，不能加成独立出刀数。两个策略各一局，不能用68.96秒和73.26秒作因果强弱结论，也不并入原四职业4/4。

这项失败提示后续应优先观察**招牌循环在正常掉落和正常输入下是否容易发现、是否值得主动用**，而不是仅依据夹具成功继续增加特效。具体是掉落时机、敌人存活窗口还是操作意图造成低使用频率，当前两局不足以定因。
