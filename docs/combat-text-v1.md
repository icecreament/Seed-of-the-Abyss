# 战斗文字层次与密集命中可读性 v1

日期：2026-10-26。目标仍为“要玩起来很爽”，本轮解决“普通跳伤与招牌回报看起来一样、密集命中数字重叠”的实际展示断点，不加伤害、攻速、震屏或粒子。

## 修改前证据

修改前核对上一轮肖像收尾的 304 份冻结文件，全部相同。保存原 RunScene 源码于 output/combat-text-v1/baseline/。

before/burst.json / nova.png 是明确隔离的展示夹具：八个静止、修改为 200HP 的目标，三层种子，暂停战斗后直接调用真实 fireNova。它不是自然战斗、不是实际 Q 输入，也不代表真实场景总会有八个敌人重叠。

- 原代码生成 17 条浮字，全是 12px。
- 八个目标各自的花冢 27 与近身新星 22 完全同坐标，记录到八组重叠。
- 白色数字压在白色受击闪烁上，没有深色描边。
- 战斗已暂停，但全局 tween 在 650ms 后把全部浮字销毁。
- 八个目标最终均为 151HP，总实际伤害 392。

四个招牌入口只修改已存在命中的呈现：

- 守望者：已经消耗实际格挡压力、并真正命中的那次普通反斩。
- 掠夺者：支付真实伤口的撕裂命中，包括已有近战接债与原追斩。
- 影行者：已经消耗潜行并刺中目标的破隐攻击。
- 棘语者：真实种子伤害的花冢引爆；原近身新星与种弹仍属普通伤害。

未命中不凭按键制造招牌数字。实际 HP 没下降时不显示伤害浮字。

## 密集布局与边界

- 场景总量最多 32 条；同一所有者同时最多三条。
- 短距离固定候选位置，带少量上升空间，不把数字甩到战场另一端。
- 密集场景优先保留受伤、招牌和暴击。空间不足可以省略普通浮字，完整伤害结算与统计不变；这不是保证“每个伤害事件都可见”。
- 不允许无位置时退回原点强行重叠。重要反馈可替换附近较低优先级数字，但不挤掉另一个刚产生的同优先级回报。
- 更新完全取战斗 delta。暂停、三选一和原命中停顿均不吃掉显示寿命。
- 下一层清空，退出场景销毁；不创建额外全局计时器、tween 或持久事件监听。
- 舒适设置关闭动态效果、或系统请求减少动态效果时，仍显示数字与层次，但取消小幅上升。

第一版探索确实仍太挤，exploration-1 的无位置回退会使密集文字重新堆叠，因此删除该回退。exploration-2 保留八条花冢回报及原说明，弱跳伤让位，九条文字无同坐标重叠，仍为相同 392 实际伤害。该极端夹具不等于所有自然战场都无文字遮挡。

## 生产源码范围

- 新增 src/systems/CombatText.ts：独立、纯展示的池、优先级、位置与时钟。
- 新增 src/ui/CombatTextPresentation.ts：场景 Text 对象的创建、同步、回收。
- src/scenes/RunScene.ts：接入新展示，标记已接受招牌攻击的文字类型，替换旧无上限 tween 浮字。

Player、Enemy、职业数值、输入、命中与碰撞、音频、画像及所有美术绘制均不改。

audit-scope.cjs 不仅检查文件哈希：它移除声明的展示接线后，必须逐字节重建完整原 RunScene，证明其余所有原游戏逻辑未漂移。只允许前轮 304 份文件中的 RunScene 变化；新增生产文件只能是上述两个展示模块。

## 保留的失败

exploratory-browser-1：守望者夹具在 Q 的原 200ms 起手无敌内立即调用伤害，当然未产生格挡压力，普通命中只有 16。修改夹具等待原保护结束，并通过接触伤害路径真正扣血/蓄势；不改生产无敌时间、不删除 18px/实际伤害断言。exploratory-browser-2 为 18/18；增加真实命中停顿与三选一生命周期后 exploratory-browser-3 为 20/20。

## 仍未验收

读得清关键回报，是整体爽感的一部分，不代表四职业整体平衡、操作学习成本、关卡节奏与主观享受已经完成。自动输入样本不等于人类首玩，模拟触屏不等于手机真机。正常场景的文字遮挡、视觉偏好与字体大小仍需实际试玩反馈；不能由结构阈值自动判定“更爽”。
