# 影行者：让切入与破隐真正衔接（2026-10-22）

## 原问题与证据

本轮不把此前整章影行者第三层死亡直接归因于数值，也不把随机重跑胜利当成平衡完成。先验证一个具体操作问题：长按攻击，再按暗影步，目标还在刀距外时会不会落地空挥、浪费破隐。

旧代码的真实键盘隔离复现见 `output/shade-flow-v1/baseline/`：目标初始距离210，暗影步之后仍不在刀距；普通空挥后一直按着Space，按Q。落地观测攻击次数由1增到3、伤害为0、隐身结束。未改控制器、伤害、速度、刀距或时钟来制造结果。这里证明的是空挥衔接问题，不证明它导致此前的自然死亡。

## 改动规则

- **长按续攻**：仅在影行者隐身期间，尚无可命中的敌人、也无可斩碎的敌弹时暂不出刀。可以继续移动、瞄准、冲刺；有机会后按原攻击冷却出刀。
- **主动出刀**：抬起后重新按Space／鼠标／触屏攻击仍可朝空处出刀、主动破隐。并非强制锁敌，不替玩家转向，不增大刀距、角度或命中半径。新按键也不能跳过原有冷却或暗影步突进锁。
- 操作系统重复keydown的repeat标记仍视为长按，不伪装成新的主动破隐；原事件对象去重继续生效。
- 机会判定与实际命中共用原有近战扇区函数；有效敌人仍必须活跃且已过生成保护。
- 碎弹机会与实际碎弹共用谓词：敌方、活跃、寿命大于0、110半径内且有墙体视线。无需瞄准弹体；友弹、死弹、远弹、隔墙弹不诱发破隐。Boss地刺不是弹体。
- 隐身仍只有原1600ms，暗影步冷却5500ms、破隐220%、原暴击／觉醒逻辑不变。等待不延长隐身、不返冷却、不额外减伤。到期后长按恢复普通连击。
- `Player.tryAttack()`没有修改伤害、技能消耗或演出规则；场景在长按续攻时决定是否提交攻击。
- 新增一对克制的紫色蓄刃提示：仅落地隐身时可见，朝向与当前出刀一致；冷却未就绪时变暗。没有额外震屏、闪白、粒子或全屏层。每个Run只建一个Graphics，重开销毁；暂停／融合不吃隐身时间。
- 中英文选人说明写明长按择机与重新按下主动出刀；核验详情文本仍在原82高面板内。

## 已处理的采集问题

- 隔离暂停夹具的新Run音频尚未解锁，不能用它断言真实破弹音。保留失败于 `iterations/audio-fixture-locked/`，该夹具先显式解锁再核验；真实Q＋碎弹音仍由原ambush真实输入用例独立验证。
- 触屏夹具曾错误地用带剩余触点的CDP touchEnd释放技能手指，实际攻击手指也失去持有；随后重加攻击触点等于一次主动出刀，造成空挥后只打出15普通伤害。`iterations/touch-audit/touch-flow.json`保留了这次完整攻击提交轨迹，明确出现buffered:true、held:false，不能伪称自动门禁失效。
- 按本地Playwright CDP协议定义，touchEnd必须无触点；通过touchMove更新活跃触点列表才保留攻击手指并释放技能手指。修正夹具后同时断言攻击持有仍为true、指针所有者相同，再用左摇杆靠近目标，首击33。未修改生产触屏逻辑、延长隐身或放宽伤害断言。
- 旧失败记录保留，不覆盖成通过。`final/`为早期迭代；本轮正式完整验证单独使用 `verified/`，以防将迭代截图或日志冒充最终结果。

## 留给真实试玩的体验问题

自动化只验证操作与规则。后续人工试玩仍应检查：

1. 一直按住攻击切入时，是否自然地接上首击，而不是感觉角色“吞了攻击”？
2. 两枚蓄刃是否足以说明“还留着破隐”，且不掩盖敌人起手？
3. 玩家希望马上出刀时，松开再按的控制是否清楚、响应是否及时？
4. 隐身到期后普通攻击衔接是否自然；低帧率和实体手机上是否仍成立？
5. 择机续攻有没有过度替玩家决策？如果人工体验不认可，需要重新评价交互，而不是用测试通过证明设计正确。

这些问题尚不能由本轮机器人通关或截图代答；整体“要玩起来很爽”的目标继续保留。
