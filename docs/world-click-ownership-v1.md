# 战场鼠标攻击归属 · v1

## 这轮解决什么

目标仍是「帅、爽、四职业有招牌感」，本轮先修会破坏操作意图的输入问题，不添加职业、伤害或特效。

原 `TextButton` 已正确拦截按下事件，但 `RunScene.readInput` 无条件读取全局左键按住状态。鼠标从音效/暂停按钮按下，仍会触发长按普攻。

### 修改前的真实证据

- `output/world-click-ownership-v1/baseline-play/baseline.json`：四职业 × 音效/暂停共八次实际 380ms 鼠标按住；场景 pointerdown 均为 0，却均出现 2 次普攻。正常时钟，清空敌人并禁止生成的隔离夹具，不是自然游玩。
- `baseline-play/shade-ui-ambush.json`：真实 Q 落地后，在 HUD 瞄准方向布置一个静止 200HP 目标，按住音效 180ms。原行为误打 33，消耗潜行并产生回身窗口。

## 生产改动

- 新增 `src/input/WorldPointerAttack.ts`：只接受传到战场的鼠标左键按下作为长按攻击所有者。未归属的按住轮询不能获得攻击权，释放或生命周期重置后必须重新按下。
- `src/scenes/RunScene.ts`：保留快速点击的原排队攻击，只替换桌面鼠标长按来源；注册匹配释放、画布外释放、引擎 blur/hidden，并在退出时解除监听。
- 暂停/恢复、三选一、进入下一层、结束、重开和失焦清理旧归属；直接进入下一层同时清理旧排队动作，避免跨层偷出刀。
- 战场开始的长按移过 HUD 不被打断；UI 开始的拖动移入战场仍不能攻击。右键释放及其他手指释放不误清理仍按住的左键。
- 空格与虚拟触控攻击继续独立生效。没有改 TextButton、Player、职业数值、碰撞、伤害、瞄准、冷却、战斗美术或肖像。

## 验证入口

- `npm run test:world-click`：8 个独立模型检查，其中 10000 次确定性交错是一个模型检查，不按样本夸大计数。
- `npm run test:world-click:browser`：真实键鼠、模拟触屏与明确标记的引擎生命周期夹具；四职业八次 HUD 按住、战场快按/长按、拖动方向归属、空格并行、33 潜行首击/回身、跨层/重开、四档倍率/中英文、半透明按钮、画布外释放及监听器销毁。
- `npm run test:world-click:natural`：独立声明的鼠标普攻控制器，派生自原整章控制器；移动、瞄准、Q、冲刺及选项策略不变。进入游戏及每次三选一后，先移动到战场 (800,360)，再真实按住左键；选择时释放。全程不按 Space，不写玩家/敌人/计时器等游戏状态，一职业一个新档正常时钟样本，不用重跑挑绿。
- 原 Space 自然控制器未改；不把其旧胜利冒充本轮鼠标证据。自然控制器只证明其声明策略下的运行，不证明人类发现性、主观爽感或真机体验。

## 保留的失败和修正

- `regression-01.txt`：旧通用鼠标夹具未调用 setupInput，缺少真实生产 pointerdown/up 绑定，且指针没有 button=0，过去无条件轮询掩盖了问题。只补齐夹具接线与 button 字段，原 144 个断言全部保留；修正后 `regression-02.txt` 为 144/144。
- `exploratory-01` 模型发现空所有者 null 与非法查询 null 相等。生产模型显式拒绝空所有者，防止其被当作已获得攻击权。
- `exploratory-01` 浏览器观察器跨场景重开包装了同一方法，导致按钮次数被重复计数；改为观察后恢复原方法，不放宽次数断言。
- `exploratory-02` 在音效按钮上释放右键触发了按钮原有行为，无法用于证明「左键从战场移过 HUD 不会点击按钮」。将右键释放移到战场，单独测试右键与左键归属；没有改变按钮的右键行为。
- `exploratory-03` 新按下等待条件仍用整局攻击数 >0，早于新一击。改为等待相对此次按下前的增量。
- `exploratory-04` 触屏夹具错误地把 touchEnd 的 points 当作剩余手指，实际结束了攻击手指。`inspect-touch.txt` 的 DOM touches/changedTouches 证明这一点；改为结束第二手指，保留「攻击仍按住」断言。正式中英文夹具也改用项目支持的 zh/en 代码。
