# 战斗 HUD 让位（2026-10-21）

## 问题与解决方式

正常地图的镜头在边缘会被边界限制，角色可能进入底部技能卡背后。Boss 冠骨也可能进入顶部标题/血条区域。不能靠移动真实碰撞体、缩小角色或增加不可见边界来掩盖遮挡。

本轮用上下文式 HUD 让位：保持布局和输入区域不动，仅降低相关区域的实心底板和装饰的遮挡，保留血量、冷却、按钮文字和触屏轮廓。

## 行为

- 保护玩家完整精灵边界（含 18px 提前量）、220 范围内的可攻击敌人、Boss 完整冠骨，以及 180 范围内的敌方弹体。
- 根据相机的真实 scroll/zoom 与画布渲染倍率投影到 HUD 的 1280×720 设计坐标，不拿世界坐标直接碰 UI。
- 约 65ms 让位；离开区域后保持 240ms，再用 220ms 恢复。长帧先消费保持时间，不能一帧把保持和恢复全跳完。
- 只让受影响的面板变淡，不把整个 HUD 一起隐藏。
- 顶部生命条最低 85%、生命数字最低 90%；底部冷却条最低 85%、冷却数字最低 90%。大块实心背景最低 5–6%。
- 暂停/SFX 按钮仅背景和装饰变淡，文字最低 90%，命中区和按下/抬起路径不变。
- 生命、冷却、计时、百分比、Boss 破绽与按钮标签使用 2px 深色描边，在亮色核心、角色和地板上也不依赖实心底板提供对比度。
- 手机只减少摇杆和按钮的填充，保留边框、标签、冷却和拖瞄反馈；不改触摸半径、手指归属或手势逻辑。
- 连斩/横幅用独立父容器让位，不覆盖它们原有的淡出动画 alpha。
- 暂停、三选一、结束时恢复常规 HUD；这些视觉过渡用 UI 时间，不推进战斗/冷却。
- 重开重新注册，离场清理，不继承上一局的让位进度和对象引用。

## 实现位置

- `src/ui/CombatHudFocus.ts`：纯投影、区域相交、时间保持/渐变、分层透明度管理。
- `src/scenes/RunScene.ts`：战斗焦点收集，生命/进度/技能/按钮/横幅/连斩分层；冷却遮罩和细条分离。
- `src/input/VirtualControls.ts`：按触屏操作区单独减少实心填充。

## 验证入口与证据

- `npm run test:hud`：投影、相交、时间窗口、长帧与拆帧一致性、随机时间步与生命周期。
- `npm run test:hud:browser`：实际 Phaser/Arcade/Canvas、四倍率、生命/冷却保留、按钮真实点击、Boss 冠骨、附近威胁、防抖、三选一、动画所有权、触屏手势与旋屏。
- `output/hud-focus-v1/browser-checks.json` 与 `model-checks.json` 是结果，不拿脚本启动状态代替通过。
- `*-solid.png` / `*-peek.png` 是隔离 UI 对比；冻结动作后只切换让位渲染，角色位置和碰撞体相同，不能冒充自然整章截图。
- `hud-before-after.png` 为底部遮挡的并排裁切对比。
- `chapter-playtests/` 用另一个正常时间、只发送输入的控制器验证整章，约束见 `docs/boss-feel-v1.md`。

## 验收边界

这不是动态重排或彻底移走所有文字：关键细条和数字仍可能叠在少量战斗像素上，目的是去掉大块不透明遮挡，同时保留决策信息。手机测试仍是浏览器触屏模拟，不能代替安卓/iOS 真机。自动通关和 UI 检查不能证明主观爽感已完成。
