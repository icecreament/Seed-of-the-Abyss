# 掠夺者追斩：击杀后主动接敌（2026-10-22）

## 目标

让掠夺者的击杀回报不止回血／数值，而是一次可以主动选择的接敌动作：击杀 → 找到下一名近敌 → 前移并重新按普攻 → 踏进接斩。它不是自动寻敌位移，也不是免费闪避。

这是四职业攻击／构筑辨识度的下一步，**不是**已经完成两条掠夺者构筑路线，更不能凭自动通关宣布「爽感已完成」。现有血涌、流血和第三次葬礼保持原规则。

## 已实现规则

- 只有掠夺者击杀非章节Boss的敌人才获得 **1200ms 战斗时间**的追斩机会。每次击杀刷新，不叠加次数；本局状态，不写永久存档。
- 普攻冷却已好、玩家正在向目标方向移动，并且**重新按下**普攻时，才考虑追步。持续按住攻击、操作系统repeat或重放旧事件不算新指令。沿用原140ms新按键缓冲。
- 只选择原近战刀距之外、再往外最多54px的可见、已实体化近敌。移动方向与目标方向点积至少0.94，移动方向与瞄准方向点积至少0.75。不移动、后退、横移、无目标、目标在墙后时仍是原普通攻击，不消费机会。
- 当前近战扇区中已有敌人时，优先普通攻击，不越过近敌追后排。
- 以480px/s沿**玩家按下时的移动方向**踏进，最多64px；方向不跟踪目标、不随鼠标转弯，目标可以躲开。希望落在原刀距内10px处，但不保证移动目标必定被命中。
- 位移通过原Arcade物理与墙碰撞，不改碰撞体、不瞬移、不穿墙。独立固定物理步距离预算处理低帧率追帧，600ms追帧也不会变成600ms加速。
- 踏进完毕才自动完成这次已承诺的普通攻击；踏进本身没有攻击判定，结束后只出一刀，使用当时原伤害／暴击／血涌与原刀距。不是额外送一刀，也不重置攻击、技能或闪避冷却。
- **追步没有无敌，也不算普通冲刺。** 原闪避和血涌输入优先，取消追步；实际受击也会打断。追步不会单独触发蜕壳爆裂或破城骨槌。第三次葬礼只在实际第三刀触发，不在踏步时偷触发。
- 暂停与hit-stop冻结战斗和物理。普通暂停保留已承诺动作，恢复物理前恢复追步速度，避免白扣第一个固定步的距离预算。三选一／换层取消追斩，死亡、结算及销毁清状态并解绑监听，不能在结束恢复物理时复活旧速度。
- 新增开放式地面双刃箭头、双语就绪提示和短残影。标记复用一个Graphics，提示参与HUD让位，不新增满屏闪白或震屏。

## 实现

- `src/systems/ReaverPursuit.ts`：机会时钟、目标资格判定、承诺方向、固定物理步预算及单次出刀。
- `src/entities/Player.ts`：职业限定、物理运动、取消与终止清理；普通闪避及无敌逻辑不接入追步。
- `src/scenes/RunScene.ts`：真实击杀授权、新按键／近敌优先、到位出刀、事件／HUD／换层／暂停／结算联动。
- `src/ui/CombatPresentation.ts`、`src/i18n/i18n.ts`：地面提示及双语操作说明。
- `scripts/check-reaver-pursuit-model.cjs`、`scripts/check-reaver-pursuit-browser.cjs`：模型及真实引擎／输入验证。

`src/data/classes.ts`、`src/systems/RunBuild.ts`及原自然整章控制器未改。当前轮增量快照与统一补丁见 `output/reaver-pursuit-v1/baseline/`、`changes.patch`，不要把整个dirty工作树当成本轮改动。

## 迭代里查到的问题

1. 初版录像尝试使用Playwright的recordVideo，但本机未安装其ffmpeg二进制。浏览器还没开始用例即失败，已终止该运行，不安装依赖；改用浏览器原生canvas.captureStream和MediaRecorder留存实际键鼠夹具。
2. 手工调用World.step后直接postUpdate的斜向夹具把Body.reset后的原点／偏移校正计入位移，多算18px/32px。替换为原生World.update/postUpdate帧入口后，斜向50px和600ms追帧64px均精确通过；未修改生产位移来迎合错误夹具。旧失败保留在 `iterations/01-manual-step-fixture/`。
3. 实际暂停菜单会清零玩家速度，因此加入恢复物理前的追步速度恢复，并专门验证暂停180ms后首物理步不丢距离。不是用自动结束追步掩盖暂停问题。
4. 死亡清理夹具最初按绝对监听数1断言，却漏算了尚未cleanup的已死亡敌人监听。改为验证玩家监听实际减少1，并独立检查后续物理步没有移动／出刀。原失败保留在 `checks-02/`。

## 验证计划与证据边界

- 模型12项，其中一项含10000个固定随机方向／步长样本；样本不是10000项独立检查。
- 浏览器25项，含真实键鼠、模拟多点触屏、攻击次数／实际伤害、墙碰撞、600ms追帧、打断、暂停、三选一、四倍率、双语提示、对象／监听清理。
- 完整回归入口及原四职业新档正常速度首层／整章，以 `output/reaver-pursuit-v1/verified/` 的终止日志和哈希为准。未结束的过程不记为通过。
- 老测试的硬编码产物目录通过 **仅文件写入重定向** 保存到本轮 `verified/gate-artifacts/`；预加载器不改源码读取、断言、输入、战斗时钟或游戏状态，避免覆盖历史证据。
- 另外准备了追斩感知的掠夺者自然整章诊断：保留原移动／技能／闪避／构筑策略，只在满足可读追斩机会时松开并重新按Space。它不是原控制器，不并入原四局，也不因为死亡而反复重开刷结果。观察包装器只转发原调用并记录结果。

以上机制验证不能代替人工判断：追步是否顺手、提示是否够清楚、主动追杀是否值得冒险，以及另外三个职业后续的玩法完成度，仍待继续打磨。

## 新循环的自然使用覆盖诊断

第一版追斩感知控制器的独立掠夺者局75.27s通关，但 **实际追步0、追斩出刀0、追斩命中0**，因此该诊断退出码为1，不能拿这次通关充当新循环已被自然使用的证据。原始结果、完整视频、控制器与哈希保留在 `pursuit-natural/`、`check-pursuit-natural.cjs`、`pursuit-natural-status.json`。

检查该控制器后发现：它一面持续长按普攻，一面只在90ms观测时恰好看到 `attackReady` 才重新按键；真实场景每帧就绪即消费长按普攻，这种采样策略不能可靠使用新按键机会，也忽略了已有140ms输入缓冲。不能把这个覆盖缺口改写为「自然玩法已验证」，更不能为测试改变生产冷却或把长按改成自动位移。

第二版是**另一个、单独记录**的输入覆盖诊断：有击杀机会且目标在刀外时松开长按，利用原140ms缓冲重新按下；进刀距后恢复普通长按。移动、技能、闪避、三选一策略不改，生产代码不改。这是控制器输入策略变更，不是同一策略重开刷胜利；其成绩不并入正式四局，也不覆盖第一版失败。

第二版已终止退出码0：新档正常速度整章67.73s通关，记录 **9次实际发动、8次完成出刀、8次命中事件**（其中一次发动未完成，保留原过程）。首个自然追斩实际按原普通攻击造成19伤害。源指纹前后相同，无属性、刷怪、坐标、时钟或生产源改写。这只能证明该输入策略在这一局自然战斗里用到了新动作，不把它当成比第一版快多少的因果对照，不并入正式479项／4局／4局结果。
